# Inni - an Anki-compatible flashcard app for macOS and iPhone

[![CI](https://github.com/asahium/inni/actions/workflows/ci.yml/badge.svg)](https://github.com/asahium/inni/actions/workflows/ci.yml)

Inni is a native spaced-repetition app that works on Anki's own files. It opens a `collection.anki2` directly, imports and exports `.apkg` and `.colpkg`, and schedules and renders cards the way Anki does, so you can switch between the two at any time. It is written in Swift with no dependencies: the app uses about 30 MB of memory and no CPU while idle.

What it does:

- **Layout.** On the Mac, one window holds the deck tree with its New/Learn/Due columns on the left and the selected deck on the right: its counts, Study Now, today's numbers, the coming week and the card mix. Studying happens in the same place, and `Esc` goes back. The deck tree takes vim keys (`j`/`k`, `h`/`l` to fold, `g`/`G`), and `Return` or `Space` starts studying. The browser has Anki's sidebar of decks, note types, tags, flags and card states. It uses Kveikur's Nord colours with monospaced lists, and is dark only.
- **Anki's collection format.** Reads and writes schema 18 (the format of current Anki), upgrades older schema-11 files, and keeps Anki's change markers so the file stays valid for Anki. On the Mac it can open an Anki profile in place while Anki is closed.
- **Scheduling.** Anki's v3 scheduler with SM-2 or FSRS-6, including learning steps, fuzz, daily limits that cascade down the deck tree, sibling burying, leeches and undo. FSRS memory states and parameters trained in Anki are used as-is.
- **Cards.** Anki's template language (conditionals, filters, `{{cloze:}}`, `{{type:}}`, `{{hint:}}`, furigana, TTS) and the stock note types with Anki's exact templates and styling. Audio and TTS play natively.
- **Packages.** `.apkg` in both the current (zstd) and legacy formats, merged by note GUID so re-importing adds nothing. A `.colpkg` replaces the whole collection, and the previous one is kept.
- **Browser.** Anki's search syntax (`deck:`, `tag:`, `is:due`, `prop:ivl>10`, `rated:7`, `re:`, `field:value`, `or`, `-`, parentheses), with bulk actions: change deck, flag, suspend, tags, forget, set due date, delete.
- **Editing.** Add and edit notes, cloze shortcuts, sticky fields, images and audio. Note types can be edited, with field renames and reordering that keep the note content.
- **Statistics.** Today, a forecast, review history, retention and card counts.
- **Sync.** AnkiWeb sync (protocol 11, the one current Anki uses): two-way merges of notes, cards, review history, deletions, decks, presets, note types, tags and settings, one-way upload or download when the two sides can't be merged, and media sync. It also works with a self-hosted `anki.syncserver`. Media sync state lives in Anki's own `collection.media.db2`, so a profile shared with Anki doesn't upload everything again. Only the sign-in token is kept, in the Keychain.
- **Backups.** One snapshot a day, keeping 14, plus one before every full download.

## Compatibility checks

The test suite compares Inni with the real Anki (the `anki` Python package) on the same collections:

- due counts per deck, rendered questions and answers, and FSRS memory states match;
- on synthetic SM-2 and FSRS collections with cards in every state, the next interval Anki picks for each rating is one Inni's formulas give for some fuzz value (Inni draws fuzz from its own generator, so the picks themselves differ). SM-2 matches on every card; under FSRS up to 1% of cards with a memory state but no review history still fall outside, and the cause is open;
- `make verify` writes a collection and packages with Inni, then has Anki open the collection, run Check Database, and import the `.apkg` and `.colpkg`;
- `make sync-test` starts Anki's own sync server and syncs Inni against Anki's backend as the second device: download into an empty collection, changes of every kind both ways, media both ways, and a schema change that forces a full upload, which Anki then downloads and checks. `SYNC_LARGE=<collection.anki2>` adds a run with a large collection (17,000 notes: full upload 0.1 s, a sync of 1,500 changes 0.04 s against a local server);
- every note type, deck and preset in the fixtures converts to the sync format and back without a single changed field.

The oracle fixtures are generated by `scripts/oracle.py` and `scripts/oracle_synthetic.py` from a copy of a collection; Inni never modifies the original.

## Build

```sh
make app       # build/Inni.app
make test
make verify    # needs a Python with `pip install anki` (ANKI_PY=...)
make sync-test # same Python; runs a local Anki sync server
make ios-sim   # iOS simulator
make ios-device
```

It needs Xcode 16 or newer. The iPhone app is in `iOS/` (xcodegen). `make ios-device` installs it on a paired iPhone; a free Apple ID signs it for 7 days, and `make ios-autosign` re-signs it over Wi‑Fi before that runs out. On the iPhone the collection is `Documents/collection.anki2`, visible in the Files app, and `.apkg` files open in Inni from Files, Mail or AirDrop.
